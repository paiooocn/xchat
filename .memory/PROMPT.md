# 注入用系统提示词

## 一句话结论

- **协议正文的权威出处是 `.memory/README.md` 的 §2 与 §4**，别处不复制副本。
- **注入块**（本文件下方）= 一段自包含的提示词，贴进任何 agent 的系统提示词即可。
- **不需要 `AGENTS.md`**：本项目（XChat）不会读它；留着只会制造"已经自动生效"的错觉。
  别的 harness 若支持该约定，需要时再临时建一个一行文件即可（见场景表）。

---

## 注入块（推荐）

```
本仓库的记忆索引在 .memory/ 下（工作目录即仓库根；XChat 会话会把「工作空间根目录」自动写在提示词首行）：开始任何改动前读 .memory/README.md 与 .memory/STATE.md 并按其中「启动协议」执行，会话结束前按「维护规则」更新索引。
红线：索引是路由不是内容，行为以源码为准；引用代码写「路径 + 符号名」，不写行号；不要擅自改 DESIGN.md 的设计结论。
```

**极简版**（只保留指针，红线靠 `README.md` §2 承载）：

```
本仓库的记忆索引在 .memory/：开始任何改动前读 .memory/README.md 与 .memory/STATE.md 并按其中「启动协议」执行，会话结束前按「维护规则」更新索引。
```

## 场景对照

| 场景 | 做法 | 注意 |
|---|---|---|
| **XChat 应用内** | 把注入块存进**会话模板**的「系统提示词」，以后从该模板建会话即自动带上 | 系统提示词是会话级字段（`system_prompt`，写入会话 XML）；`.memory/` 是相对路径，**会话工作目录须指向仓库根** |
| 临时会话 | 直接把注入块粘进会话的系统提示词 | 同上 |
| 别的 harness（不读仓库文件） | 贴 `README.md` 的 §2 + §4 | 不要另抄一份 |
| 支持 `AGENTS.md` 的 harness（如 Codex / Cursor） | 需要时在仓库根建一行 `AGENTS.md` 指向 `README.md` | **不必常驻**，用完可删；XChat 不读它 |

XChat 侧补充：会话系统提示词首行会被 `injectWorkspaceRoot` 写入 `工作空间根目录: <sandbox>`
（绝对路径），所以注入块里的 `.memory/` 相对它解析 —— 这也是"工作目录须指向仓库根"的原因。

---

## 为什么不再保留 AGENTS.md

1. **零功能价值**：本项目唯一的 agent 就是 XChat 自己，`lib/` 里没有任何读取 `AGENTS.md` 的代码。
2. **有认知危害**：它让人以为协议已经自动接上了。实际发生过 —— 本文件曾把一个"仓库级自动注入（已启用）"的
   提示块当成生效方案写在这里，而那条路径根本不工作。
3. **恢复成本近乎为零**：真需要时一行就能建回来。

判断标准很简单：**只有会被真正读取的文件才该留在仓库里**。

## 层次职责

| 层 | 文件 | 谁写 | 会不会过期 |
|---|---|---|---|
| 注入块 + 场景 | `.memory/PROMPT.md`（本文件） | 手写，短 | 随场景变 |
| **协议正文** | `.memory/README.md` §2 + §4 | 手写 | 改协议只改这里 |
| 事实 | `.memory/MAP.yaml` | 生成器 | 会 —— 用 `--check` 检出 |
| 判断 | `.memory/ANNOTATIONS.yaml` | 人 / Agent | 靠收尾协议维护 |
| 结构 | `.memory/ARCHITECTURE.md` | 人 / Agent | 慢变 |
| 坑 | `.memory/GOTCHAS.md` | 人 / Agent | 只增不减 |
| 进度 | `.memory/STATE.md` | Agent（每次会话） | 总是最新 |

**生成器与手写层分离**，所以重新生成 `MAP.yaml` 永远不会覆盖掉人的判断；
而 `--check` 能把"代码已变、索引没变"变成一个可被 CI 捕获的失败。
