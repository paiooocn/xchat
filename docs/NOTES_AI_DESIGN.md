# 功能设计：带 AI 助手的 Markdown 笔记

> 状态：**设计稿（未实现）**
> 目标版本：待定（建议 v0.7.x）
> 相关既有能力：`lib/ui/widgets/markdown_view.dart`（Markdown 渲染）、
> `lib/ui/widgets/math_support.dart`（公式）、`lib/llm/prompt_assistant.dart`（应用级流式 LLM 调用范式）、
> `lib/state/app_state.dart` 的 `appFeatureTarget`（应用功能调用模型）

---

## 1. 目标与范围

给 XChat 增加一个**独立于会话**的笔记工作区：用户用 Markdown 写笔记，右侧有一个
能读懂当前笔记的 AI 助手，可以对笔记做**改写 / 生成 / 问答**三类事。

**范围内**

- 笔记的增删改查、标签、置顶、搜索、归档
- **与「会话」合并为同一工作区的两个侧栏 Tab**（不新增路由、不新增页面）
- Markdown 源码编辑 + 实时预览（复用现有渲染管线，公式/代码高亮/表格全部沿用）
- AI 助手侧栏：选区改写、整篇生成、基于笔记的问答
- AI 结果以 **diff 预览 → 用户确认** 的方式写回，不允许静默覆盖正文
- 与现有体系打通：笔记 ↔ 会话（双向，可选，二期）

**不在范围**

- 富文本（所见即所得）编辑器 —— 现有依赖里没有富文本引擎，且 Markdown 源码 + 预览
  已覆盖笔记场景；一期不做
- 多端实时协同、笔记图谱/双链、OCR
- 笔记内嵌附件（图片等）—— 一期只支持纯 Markdown + 外部相对路径引用

## 2. 现状盘点：能直接复用什么

| 能力 | 复用点 | 说明 |
| --- | --- | --- |
| Markdown 渲染 | `markdownView()`（`lib/ui/widgets/markdown_view.dart`） | 已封装好：代码围栏高亮、行内代码、引用、表格（`FlexColumnWidth`，避 dry-layout 崩）、KaTeX 公式、选中复制保换行。笔记预览**直接调用它**，不重写渲染器 |
| 公式 | `math_support.dart` 的 `mathInlineSyntaxes` / `mathSpanGenerators` | 预览自动带 `$…$` / `$$…$$` |
| 应用级 LLM 调用 | `lib/llm/prompt_assistant.dart` 的 `_stream()` + `llm.CancelToken` | 笔记 AI 走同一条路：`createProvider()` → `provider.stream()` → `onProgress` 增量 → 结束时清围栏/去前缀 |
| 模型选择 | `AppState.appFeatureTarget` | 笔记 AI 默认用「模型服务」页选中的应用功能调用模型；可在笔记页临时切 |
| 落盘原子性 | 现有 repository 的「写 `.tmp` 再 rename」 | 笔记保存沿用 |
| 索引缓存 | `lib/models/catalog_index.dart` + `lib/data/index_repository.dart` | 笔记列表加第 5 个桶 `notes`，摘要进 `index.json` |
| 归档/删除交互 | `lib/ui/widgets/confirm_dialog.dart` | 复用 `confirmDelete` / `confirmDeleteProject` 风格 |

> **不变量提醒**（见 `.memory/ARCHITECTURE.md`）：
> 序列化只写在 `data.xml` 层；UI 不直接碰文件系统；全局状态只有 `AppState`。
> 本设计的落盘位置、索引字段都必须遵守。

- 笔记 Tab 下，主区 = 上预览 / 下编辑 + AI 边栏；会话 Tab 下，主区 = 现在的聊天区。
- 底部工具条（审批 / 模板 / 更多 / 主题）两态共用。

## 4. 数据模型与存储

### 4.1 落盘格式：Markdown 文件 + front-matter

一篇笔记 = 一个 `.md` 文件，放在 `<root>/notes/`：

```markdown
---
id: 9f2c1e0a-...
title: 会议纪要 · 2026-11-04
tags: [会议, 项目A]
created_at: 2026-11-04T09:12:33Z
updated_at: 2026-11-04T10:02:11Z
pinned: false
archived_at: null
---

# 会议纪要 · 2026-11-04

- 讨论了 …
- 结论：**下周三前交付初稿**

> 引用、代码块、$公式$ 都能用
```

**为什么用 Markdown 文件而不是会话那样的 XML**

1. 笔记的产物是**给人读、给别的工具读**的内容，`.md` 可被外部编辑器、git、
   `grep` 直接消费，天然跨工具；
2. 正文即文件，用户用「用编辑工具打开」（现有 `editor_launcher` 能力）就能改；
3. 会话 XML 的复杂度（消息、工具调用、usage）笔记全都不需要。

**代价与对策**

| 代价 | 对策 |
| --- | --- |
| 元数据需要嵌入正文 | front-matter 固定 key 集；解析器只认白名单 key，未知 key 原样保留（不丢信息） |
| 列表页要读文件头 | 只读文件前 4KB 解析 front-matter + 正文首行做摘要；并用 `index.json` 缓存摘要 |
| 并发写冲突 | 单实例应用；写盘走「tmp + rename」原子替换；外部改动在失焦时重载并提示「文件已在外部变更」 |

### 4.2 front-matter 契约

| key | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | string | 是 | UUID，文件名亦为该 id |
| `title` | string | 是 | 显示标题；为空时取正文首个 `# ` 标题 |
| `tags` | list | 否 | 逗号分隔，解析成 `List<String>` |
| `created_at` | ISO8601 | 是 | UTC |
| `updated_at` | ISO8601 | 是 | UTC |
| `pinned` | bool | 否 | 置顶，默认 false |
| `archived_at` | ISO8601\|null | 否 | 归档时间；非空则不进活动列表 |

> 遵守不变量 10（新字段必须能读旧文件）：front-matter 缺 key 走默认值，
> 未知 key 保留；正文缺 front-matter 的裸 `.md` 文件可被导入为笔记（补齐头部）。

### 4.3 索引（index.json）扩展

`CatalogIndex` 增加第 5 个桶 `notes`（只放摘要，不放正文），`version` 由 **4 → 5**：

```json
{ "id": "...", "title": "...", "tags": ["会议"], "created_at": "...",
  "updated_at": "...", "pinned": false, "archived_at": null,
  "preview": "会议纪要 · 讨论了…（正文前 80 字）" }
```

- `IndexRepository.rebuild()` 扫 `notes/` 目录解析 front-matter；
- `_matchesDisk()` 增加对 `notes/` 目录 id 集合的校验；
- 归档笔记仍进 `notes` 桶（用 `archived_at` 区分），与项目/会话的
  「四桶」做法保持一致的读写习惯（会话是分 `sessions`/`archived_sessions` 两桶，
  项目同理；笔记数量级小，一桶 + 字段区分即可，UI 过滤时再分）。

### 4.4 冲突与保存

- **自动保存**：编辑停止 800ms 后自动落盘，AppBar 显示「已保存 / 保存中…」。
- **手动保存**：`Ctrl+S`（桌面）/ AppBar 保存按钮。
- **外部修改检测**：编辑期间记录打开时的 `mtime`；失焦或保存时若 `mtime` 变了 →
  弹「磁盘上的笔记已变更」→ 用户选「重新加载（丢弃本地修改）」或「保留本地（覆盖）」。
- **删除**：软删 → 进归档（`archived_at`）；彻底删除需二次确认（复用 `confirmDelete`）。

## 5. 界面设计

### 5.1 入口：**与「会话」并列的侧栏 Tab**

笔记**不再是独立页面**，而是 `HomePage` 左栏的一个 Tab —— 与「会话」并列，
点一下就切过去。

- 位置：侧栏**顶行下方**一行 Tab：`会话 | 笔记`（分段控件样式，带小图标）
- 切换后：
  - **左栏**内容替换 —— 会话 Tab 显示「项目 / 全局会话树」，
    笔记 Tab 显示「搜索 + 置顶 / 最近 / 标签 / 归档」的笔记列表
  - **主区**内容替换 —— 会话 Tab 是聊天区（消息流 + 输入区），
    笔记 Tab 是「上预览 / 下编辑」+ 右侧 AI 边栏
- 状态各自保留：切走再切回来，选中的笔记、编辑区高度档位、AI 边栏开合都原样恢复

> 不新增底部导航项、不新增路由：笔记是会话工作区的**另一个视图**，不是另一个目的地。

### 5.1.1 侧栏顶行调整：「新建会话」从「行」变「按钮」

原来侧栏里有一整行「＋ 新建会话」（`_navList` 的快捷入口行）。现在：

- **移除该行**（`_navEntries` 里只剩它一项，整行快捷入口列表随之取消）
- 「新建会话」改为**顶行的一枚图标按钮**，放在「刷新会话列表」**右侧**：

```
┌ 顶行 ────────────────────────────────────────────────┐
│ [X] XChat          [↻ 刷新] [＋ 新建会话] [⌂ 回到首页] │
└──────────────────────────────────────────────────────┘
```

- 「新建会话」按钮用**主色实心**（圆形/方形 primary 图标按钮），是顶行唯一的强调色
- 笔记 Tab 下，同一个位置变成「＋ 新建笔记」（同一个 widget，换图标与 tooltip）
- 「刷新会话列表」在笔记 Tab 下语义变为「刷新笔记列表」（换 tooltip，行为对应各自的列表）
- 快捷键：**现状 `Ctrl+N` 只是那一行里的文案标签，全仓没有真实按键绑定**；
  删掉该行后提示一并消失。若要真快捷键，需**新写**绑定（`Ctrl+N` 新建会话 /
  `Ctrl+Shift+N` 新建笔记）——属新增能力，单列一条任务，不混在本次改造里

### 5.2 桌面（≥ 1080px）

会话 Tab 与笔记 Tab 是同一个外壳的两种状态：

```
┌ 会话 Tab ────────────────────────────────────────────────────────────┐
│ [X] XChat        [↻刷新][＋新建会话][⌂]                              │
│ ┌ 会话 ┬ 笔记 ┐                                                      │
│ │ ▾ 项目 │                                                          │
│ │ ▾ 全局会话                    [主区：聊天区]                        │
│ └────────────┬─────────────────────────────────────────────────────┘ │
└──────────────┴────────────────────────────────────────────────────────┘

┌ 笔记 Tab ────────────────────────────────────────────────────────────┐
│ [X] XChat        [↻刷新][＋新建笔记][⌂]                              │
│ ┌ 会话 ┬ 笔记 ┐                                                      │
│ │ 搜索笔记… │                         ┌ AppBar ────────────────────┐ │
│ │ ▾ 置顶    │                         │ 会议纪要·2026-11-04        │ │
│ │ ▾ 最近    │                         │        [40%|20%|收起] [收起AI][⋮] │
│ │ ▾ 标签    │                         ├── 上区：预览 ──────────────┤ │
│ │ ▾ 归档    │                         │  # 会议纪要                │ │
│ │           │                         │  ## 议题 …                 │ │
│ │           │                         ├── 分隔条（可拖） ──────────┤ │
│ │           │                         │ 下区：编辑（源码，等宽）    │ │
│ │           │                         │  状态：已保存 · 1,204 字    │ │
│ └───────────┴─────────────────────────┴────────────────────────────┘ │
└──────────────────────────────────────────────────────────────────────┘
```

左栏（288px）在两种 Tab 下**结构相同**：顶行（品牌 + 刷新 + 新建 + 回家）、Tab 行、
列表区、底部工具条（审批 / 模板 / 更多 / 主题）。只有列表区的内容与主区跟着 Tab 变。

#### 5.2.1 笔记列表（笔记 Tab 的左栏）

- 顶部：搜索框（标题 / 正文 / 标签全文匹配，实时过滤）
- 分组（顺序固定）：**置顶 → 最近 → 标签 → 归档**
  - 「最近」按 `updated_at` 倒序，条数上限 20；
  - 「标签」是标签的并集，每个标签显示计数；点击 = 过滤该标签（可多选，AND）
  - 「归档」默认折叠，展开可恢复 / 彻底删除
- 行内容：标题（1 行截断）· 摘要（1 行，`onSurfaceVariant`）· 标签 chip · 时间
- 行菜单（⋮）：重命名 / 编辑标签 / 置顶 / 复制 Markdown 原文 / 用编辑工具打开 /
  导出到文件 / 归档 / 删除
- 空态：插画占位 + 「新建笔记」按钮 + 一行提示「⌘N」

#### 5.2.2 笔记主区：上预览 / 下编辑（**一套布局，不做模式切换**）

笔记 Tab 的主区**只有一种布局**。原来的「编辑 / 分屏 / 预览」三选一模式切换被取消，改成
**固定的上下分屏**：上区预览、下区编辑，用户只调「下区多高」这一个量。

```
┌──────────────────────────────┐
│  上区：预览（flex，自适应）    │  ← 始终渲染 Markdown 全文
├──── 分隔条（可拖动） ─────────┤
│  下区：编辑（高度 = 档位）     │  ← Markdown 源码
└──────────────────────────────┘
```

**上区 · 预览**

- 直接调用 `markdownView()` 渲染全文 —— 公式 / 代码高亮 / 表格与聊天消息完全一致
- 源码改动后 300ms 防抖重渲
- 顶部浮层：大纲（按标题层级生成，点击跳转）、代码块「复制」；表格横向可滚动

**下区 · 编辑**

- 等宽字体（`AppFonts.mono`）+ CJK 回退；行号可选
- 工具栏做**语法包裹**而非所见即所得：选中文字 → 点「粗体」→ 文本被 `**…**` 包裹；
  光标处插入 → 插入模板片段（表格骨架、任务列表行等）
- 工具栏内容：粗体 / 斜体 / H1-H3 / 无序列表 / 任务列表 / 有序列表 / 代码块 /
  行内码 / 链接 / 表格 / 引用 / 公式 / 图片 / 用编辑工具打开
- 公式按钮插入 `$...$` 并唤起一个小的公式预览浮层

**下区高度三档（相对笔记区可用高度）**

| 档位 | 语义 | 说明 |
| --- | --- | --- |
| **40%** | 写作档（默认） | 预览 60% + 编辑 40%，边写边看 |
| **20%** | 审阅档 | 预览 80% + 编辑 20%，源码只留几行 |
| **0%**（收起） | 阅读档 | 编辑区与分隔条隐藏，预览占满；点工具栏「编辑」回到 40% |

- 档位由 AppBar 的分段控件切换，**状态按笔记持久化**（`SharedPreferences`
  或 front-matter 的扩展字段）
- 分隔条**可拖动**自由调整；拖动结果吸附到最近的档位（40% / 20% / 0%），
  保证持久化值只有三个
- 三档只改**高度**，不改结构 —— 预览永远在上、编辑永远在下，
  用户不需要在两种心智模型之间来回切换

**底部状态条**：`已保存 / 保存中… / 未保存` · 字数 · 标签 · front-matter 摘要 ·
「用编辑工具打开」

#### 5.2.3 AI 助手侧栏（右栏，可展开 / 收起）

- **两种形态**（由一个状态量控制）：
  - **展开 320px**：完整面板
  - **收起 44px**：折叠成一条竖轨 —— 顶部 AI 图标按钮（带「生成中」角标）
    + 竖排「AI 助手」文字；点击图标重新展开
- 收起时中间栏（笔记区）向右扩展，占回这 320px 宽度
- 收起状态持久化（`SharedPreferences`）；**正在生成时不收起**
  （或收起后用竖轨角标继续跑完，不中断请求）
- 展开态内容：
  - 顶部分组标签：**改写 · 生成 · 问答**
  - 主体是对话流：用户气泡（右下，浅主色底）、AI 气泡（左下，surface 容器底），
    AI 气泡内容用 `markdownView()` 渲染；流式期间显示「正在生成…」+ 停止按钮
  - 底部输入框：多行，Enter 发送 / Shift+Enter 换行；右侧「➤」；上方一行
    上下文开关：**「包含全文」**（默认开）——关掉时只把选区送给模型
  - 面板头部右上角：模型选择（默认取 `appFeatureTarget`，可临时切换）、**收起按钮**


#### 5.2.4 AI 结果写回：diff 预览弹层

AI 产出**编辑建议**时（不是纯问答），结果卡片下方给两个动作：

- **在编辑器中预览差异** → 打开 diff 弹层（居中，宽 720）
- **插入到光标处 / 替换选区 / 追加到文末**（直接在编辑器内落地）

diff 弹层：

```
┌──────────────────────────────────────────────────────────┐
│ AI 修改预览                        provider · model       │
├──────────────────────────────────────────────────────────┤
│  12行上下文                                        省略 ▾ │
│   - 讨论了改期的相关问题                              │
│ + 就改期问题达成一致，负责人：王工，截止 11 月 15 日。   │
│   - 结论：下周三前交付初稿                             │
├──────────────────────────────────────────────────────────┤
│  [接受并应用]   [拒绝]   [复制结果]                     │
└──────────────────────────────────────────────────────────┘
```

- 行级 LCS diff（红删 / 绿增），未改行折叠为「省略 N 行」
- 「接受并应用」→ 写回编辑器缓冲区（不直接落盘，仍走自动保存）→ 撤销栈支持 `Ctrl+Z`
- 「拒绝」→ 只关闭，不改内容
- **任何 AI 写入都先过这一个弹层**，不存在静默覆盖

### 5.3 移动端（< 1080px）

底部 Tab 与桌面侧栏对齐：**`会话 | 笔记`**（桌面把侧栏收进抽屉，Tab 提到底部）。

- **会话 Tab**：聊天页（与现状一致）
- **笔记 Tab** 内部是**栈**：列表页 → 编辑页 → AI 抽屉
  - 列表页：搜索 + 置顶 / 最近 / 标签 / 归档；顶行右侧是「＋ 新建笔记」图标按钮
    （对应桌面顶行按钮位）
  - 编辑页：**与桌面同一套上下分屏** —— 上预览、下编辑，下区高度同样三档
    （40% / 20% / 收起）；工具栏横向滚动吸在编辑区顶部；长按选区浮出
    「改写 / 翻译 / 摘要」快捷动作
  - AI：**底部抽屉（bottom sheet）**，高度 70%，可上拉全屏；AI 输出卡片上的
    「预览差异」在抽屉内以全屏路由打开

### 5.4 深色模式

完全跟随 `ThemeMode`；代码块沿用 `markdown_view.dart` 现有的深色预设；
diff 用「深红底 / 深绿底 + 左侧竖条」而非浅色高亮，保证对比度。

## 6. AI 助手设计

### 6.1 能力清单

**A. 改写（针对选区或全文，产出替换文本）**

| 动作 | 指令要点 |
| --- | --- |
| 润色 | 保持原意与结构，修正病句/错别字，书面语 |
| 扩写 | 每段补充论据/例子，篇幅 +50%~100% |
| 缩写 | 压缩为要点清单，去冗余 |
| 改写语气 | 正式 / 口语 / 简洁 / 客观 |
| 翻译 | 中→英 / 英→中，保留 Markdown 结构与代码块原样 |
| 纠错 | 找出事实性/逻辑性错误并给出修正（输出含「问题 / 建议」两段） |
| 转换格式 | 转表格 / 转任务列表 / 转时间线 |

**B. 生成（产出新片段，插入而非覆盖）**

| 动作 | 产出 |
| --- | --- |
| 续写 | 按当前上下文继续往下写（保持风格与层级） |
| 摘要 | 3-5 条要点 + 一句话结论 |
| 标题 | 3 个候选标题（供挑选） |
| 标签 | 3-6 个标签（直接可一键写入 front-matter） |
| 大纲 | 按现有正文生成/补全目录结构 |
| 会议纪要模板 | 从零生成会议纪要骨架（议题/结论/待办表） |
| 复习卡片 | 5 条 Q&A（自测用） |

**C. 问答（只读，不改文档）**

- 以当前笔记（全文或选区）为上下文提问
- 模型被明确要求：**只回答，不输出改写建议**
- 回答区支持「复制」「插入到文末（作为附录）」

### 6.2 上下文构造

送进模型的消息结构（system + user）：

```
system:
  你是 Markdown 笔记助手。当前笔记的标题是「{title}」。
  笔记正文是 Markdown 源码（可能有未完成的句子，不要自行补全正文）。
  规则：
  - 输出必须是 Markdown 片段，不要用 ``` 包裹整篇，不要写解释性前言。
  - 除非用户明确要求「重写全文」，否则只输出被修改/新增的那部分。
  - 保留原有的标题层级、列表缩进、代码围栏与语言标注、表格列结构。
  - 不要编造笔记里没有的事实；需要外部信息时说明「需要外部资料」。

user:
  【当前笔记正文】
  <note>
  …front-matter 之后的正文原文…
  </note>

  【本次请求】
  {指令}            ← 改写类带上选区原文与选区在全文中的上下文（前后各 200 字）
  【选区】
  {选区原文}
```

- **上下文预算**：全文超过 12k 字时自动降级为「标题 + 大纲 + 选区 + 命中关键词段落」，
  并在 UI 提示「已按相关片段裁剪上下文」；用户可在设置里调阈值。
- **选区定位**：把选区原文连同其在全文的位置（前后 200 字）一起给模型，
  避免「把第二段改正式些」这类指代歧义。

### 6.3 输出协议与后处理

- 模型输出统一约定为**纯 Markdown 片段**
- 后处理（`note_assistant.dart` 内）：
  1. 去掉包裹整篇的 ```` ``` ```` 围栏（参考 `prompt_assistant.dart` 的 `_unwrap`）
  2. 去掉「好的，」这类前缀噪声
  3. 保留内部代码围栏原样
- 改写类结果 → 进入 diff 弹层；生成类结果 → 进入「插入到光标处 / 追加 / 复制」三选一

### 6.4 模型、参数与并发

| 项 | 取值 |
| --- | --- |
| provider / model | 默认 `AppState.appFeatureTarget`（模型服务页选的应用功能调用模型）；笔记页可临时切换，临时值只作用于本次会话 |
| temperature | 改写/纠错 0.3；生成 0.7；问答 0.2 |
| max_tokens | 跟随 provider 的 `maxOutputTokensFor()`，不额外限制 |
| 思考档位 | 不传 `reasoningEffort`（与 `prompt_assistant.dart` 一致） |
| 并发 | 同一时间只允许一个 AI 请求在跑（面板顶部显示进行中），避免流式交叉 |
| 取消 | `llm.CancelToken`；面板「停止」按钮与关闭页面都会 cancel |

### 6.5 失败与边界

| 场景 | 处理 |
| --- | --- |
| 未配置任何 provider / model | 侧栏顶部提示「尚未配置模型服务」，按钮跳「模型服务」页；不报错堆栈 |
| 请求失败 / 超时 | AI 气泡内红字提示 + 「重试」；保留用户输入 |
| 上下文超限 | 自动裁剪并提示；提供「发送全文」强制选项 |
| 模型返回空 | 提示「模型未返回有效内容」（与 `prompt_assistant` 同款文案） |
| 离线 | 提示「网络不可用，请检查连接」 |
| AI 输出与原内容冲突 | 一律 diff 预览，用户决定 |

## 9. 风险与已知坑（实现时必须规避）

1. **不要把渲染逻辑重写一遍**。预览必须走 `markdownView()`，否则代码高亮、公式、
   表格列宽、复制换行这些已修过的坑会全部复现（见 `.memory/GOTCHAS.md` §8）。
2. **表格 + 公式组合会触发 dry-layout 崩溃**：`markdown_view.dart` 已用
   `TableConfig(defaultColumnWidth: FlexColumnWidth())` 规避，笔记预览复用同一函数即自动免疫。
3. **选区跨 `WidgetSpan` 会被截断**：`SelectionArea` 的选区按屏幕顺序串联，
   隐藏文本类小控件不要放进 `WidgetSpan` 子树（代码围栏已是正确示范）。
4. **AI 静默覆盖是最严重的体验事故**：写回一律走 diff 弹层 + 撤销栈。
5. **索引版本**：`CatalogIndex.version` 必须从 4 升到 5，老索引会被丢弃重建——
   这是既定机制（防止缺字段的索引静默丢数据），照做即可，不要试图兼容老版本。
6. **外部编辑冲突**：笔记是文件，可能被用户用别的编辑器改过；保存前比 `mtime`。
7. **front-matter 解析不可用正则硬啃 YAML**：只认白名单 key 的简单 `key: value`，
   未知 key 保留原文；不引入 YAML 依赖。
